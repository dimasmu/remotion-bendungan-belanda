# Flat 2D Explainer — STYLE-02

## Purpose and visual identity
A crisp vector-like explainer language for science, systems, everyday technology and process education. Communication and hierarchy take priority over decorative detail.

## Character construction
Characters are optional. When needed, use geometric heads and bodies, simplified limbs, minimal facial features and a limited set of repeatable poses. Lock head/body ratio, corner radius, limb thickness, facial feature scale and icon-like silhouette. Characters should support the explanation rather than dominate it.

## Shape grammar and linework
Use circles, rounded rectangles, clean polygons and consistent corner logic. Choose either outline-free shapes or a single controlled outline system. Keep stroke widths consistent and scale-aware. Avoid sketchy linework, painterly texture and realistic anatomy.

## Palette and rendering
Use a compact, high-contrast palette: background, primary, secondary, accent, neutral, dark text/outline and semantic colors. Exact HEX values must be declared in PALETTE.md. Prefer solid fills; gradients only as a restrained hierarchy cue. Shadows are minimal and geometric.

## Environments, objects and diagrams
Build scenes from modular shapes, simplified objects, icons, arrows, labels and data graphics. For machinery, show only components necessary to explain function. Keep diagrams orthographic or deliberately simplified; label hierarchy must remain readable.

## Layout and camera
Mostly orthographic 2D composition. Use grid alignment, generous negative space, strong visual hierarchy and smooth position/scale transitions. Avoid simulated cinematic perspective unless explicitly approved.

## Animation behavior
Animate transforms, masks, shape reveals, diagram connections and icon transitions. Use easing with clear start/end states. Keep object geometry stable; do not let icons morph unpredictably.

## Character/asset sheets
Create separate sheets only for recurring assets that need reuse. A sheet contains one character or one object family per output, not unrelated entities. Show the views needed for animation or explanation; no mandatory fixed number of poses.

## Prompt constraints
Specify exact palette, geometry, stroke/no-stroke policy, shadow style, grid and typography. Exclude photorealism, painterly texture, unnecessary details and unapproved colors.
